# session-record — セッションログ記録（＝「整理して」／書込は承認後）

作業が一段落したら Notion「AI外部脳」に記録し、次セッションへ引き継ぐ。
**Notion 書込は必ず「何を・どこへ書くか」を提示し、ユーザー承認（権限プロンプト）を得てから反映する。**

## 手順

1. **重複チェック**: `セッションログ`〔`bb13106c-1f51-4a62-ad60-aa355bbe455b`〕を当日・同主題で検索し、既存レコードがあれば新規作成せず更新する（作成前重複チェック）。
2. **草案を作る**（下記フィールド）。ユーザーに提示する。
3. **原子的に周辺レコードを登録**（該当時）: 決定→`Decisions`〔`0ac2817a-7101-4219-8537-e84414662e6f`〕（AEP は Decision Log D-001…）、未解決→`OPEN_ITEMS`〔`0e7346d9-33ad-4b86-ab04-9ea59fc62051`〕、成果物/ビルド仕様→`資料管理`〔`0d8605f9-a47c-4a37-bfae-1184ddda1b5f`〕、恒久知見/TIP→`MASTER_KNOWLEDGE`〔`06ea50af-0d77-4ab2-8179-042f03c6a97a`〕、失敗と是正（第5節3条件）→`Mistakes`〔`6e9433ff-bcff-4fe2-ba2e-3fe3fec2a0ca`〕。
4. **承認後に書き込む**（`notion-create-pages` / `notion-update-page`）。セッションログの `関連Decisions`・`関連OPEN_ITEMS`・`関連資料`・`プロジェクト` をリレーションで紐付ける。
5. 当該プロジェクトの `00_運用設計・背景` の **「現在地サマリー」を上書き更新**する。
6. **第6節（透明性）**: 書き込んだ内容（レコード名・DB）をユーザーに報告する。

## セッションログのフィールド

| フィールド | 内容 |
|---|---|
| `タイトル` | 日付＋主題（例：`2026-07-21 Claude Code×Notion連携リポ`） |
| `主題` | このセッションで扱ったテーマ |
| `検討経緯` | 議論の流れ・出た選択肢・没案とその理由 |
| `結論` | 確定したこと |
| `次アクション` | 次回セッションの出発点 |
| `ステータス` | 進行中 / 一段落 / 確定 |
| `前回との関係` | 継続 / 方針転換 / 矛盾解消 / 新規 |
| `日付` | セッション実施日 |
| `プロジェクト` | プロジェクト一覧への relation（必須） |
| `関連Decisions` / `関連OPEN_ITEMS` / `関連資料` | 該当時に relation で紐付け |

## コード連携

本リポのコード作業では、コミット/PR・生成物を `関連資料` または `資料管理` DB に紐付け、コードと知識のトレーサビリティを保つ。
